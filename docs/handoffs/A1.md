## Bauen, testen, starten

```sh
cd Packages/TimetrackCore && swift test --build-system native      # Standard `swift test` scheitert hier an codesign (xattr)
xcodegen generate
xcodebuild -project Timetrack.xcodeproj -scheme TimetrackMac -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Timetrack.xcodeproj -scheme TimetrackIOS -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

Ohne Provisioning-Profil immer `CODE_SIGNING_ALLOWED=NO`. Mit Profil funktioniert Automatic Signing (Team `J2DU2P47XW`; Mac-Build signiert ergab BUILD SUCCEEDED).
Integrationstest gegen einen Wegwerf-Server: `TT_INTEGRATION_URL=http://localhost:<Port>` und `TT_INTEGRATION_COOKIE_FILE=<Datei mit tt_session>`
(nie Port 18080); ohne diese Variablen wird er übersprungen.

## Abweichungen und Befunde

- Recovery-Sitzungen sind serverseitig auf Passkey-Einrichtung beschränkt (`recovery_session_restricted`). Die App zeigt dann einen eigenen Bildschirm
  "Passkey einrichten". Zum Arbeiten ohne Passkey gibt es nur den Debug-Cookie-Import (`#if DEBUG`). Siehe ADR-0015.
- Das CSRF-Token wird vom Server aus dem Sitzungstoken abgeleitet (stabil pro Sitzung).
- Das Associated-Domains-Entitlement ist bewusst noch nicht gesetzt (siehe unten), damit Builds ohne Profil laufen.
- `swift test` ohne `--build-system native` scheitert an CodeSign des Testbundles; mit `native` läuft alles.
- Screenshot der macOS-App: `screencapture` lieferte "could not create image from display" (kein Display für die Sitzung). Die App startete
  (Prozess lief), Oberfläche wurde NICHT visuell geprüft. Signed-in-Bildschirme sind nur über Stores/Integrationstest abgesichert, nicht per UI-Test.
- Zeit-Editor: Sommerzeit-Wechsel im DatePicker nutzt die Zeitzone des Arbeitsmodells; nicht manuell geprüft.
- Nicht umgesetzt: Orte, Vorschläge, Berichtsheft, Planung etc. (Seitenleiste nur Heute/Zeit; `requiredModule` ist für spätere Einträge vorbereitet).

## Offen / vom Nutzer nötig

- Domain mit TLS (RP-ID) für echte Passkeys; Entitlement `com.apple.developer.associated-domains` = `webcredentials:<host>` ergänzen.
- Backend A2: `/.well-known/apple-app-site-association` mit App-ID `J2DU2P47XW.de.linolaske.timetrack` (`APPLE_APP_IDS`), Origin-Prüfung.
- Bereits angegeben: Team ID `J2DU2P47XW`, Bundle-ID `de.linolaske.timetrack`; Watch später `de.linolaske.timetrack.watchkitapp`.
- Entscheidungen aus den offenen Fragen in ADR-0015.
