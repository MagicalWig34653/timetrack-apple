# Handoff E2: Kalender je Kalender lesen/schreiben, Urlaub und Krank schreiben, Glas in der Live Activity

Branch `e2-calendar-rw-glass` (Basis `main` bei Build 9), 19.10.2026. Nicht gemergt, nicht gepusht, Build-Nummer unverändert, kein Upload.

## Was gebaut wurde
- **Modus je Kalender** (`CalendarMode`: Aus / Lesen / Schreiben; „Schreiben“ schließt Lesen ein) ersetzt den globalen Schalter aus E1. Standard überall Aus. Je Gerät in `UserDefaults`, nie zum Backend. Alte E1-Einstellungen werden gelesen (ausgewählte Kalender -> Lesen; war Schreiben an, wird der Kalender „Timetrack“ auf Schreiben gesetzt und Arbeitstage bleiben an). Kalender ohne Änderungsrecht (Abos) bieten nur Aus/Lesen.
- **Geschrieben** wird in alle Kalender auf „Schreiben“, als ganztägige Termine: pro Abwesenheit (Urlaub, Krank; Status planned/approved/taken) ein mehrtägiger Termin. Titel: „Urlaub (geplant)“, „Urlaub (genehmigt)“, „Urlaub“ (genommen), „Krank“. Keine Notizen, kein Krankschein-Stand. Nicht geschrieben: requested, rejected, cancelled, Freigestellt, Sonstiges. Arbeitstage des Plans (E1) sind ein eigener Schalter, Standard aus; der Schalter für Urlaub/Krank ist standardmäßig an (wirkt nur bei Kalendern auf Schreiben).
- **Kennung**: Marker-URL `timetrack://absence/<uuid>` bzw. `timetrack://plan/<Tag>`. Nur Termine mit gültigem Marker werden geändert oder gelöscht (Planer `CalendarWritePlanner`; der EventKit-Provider prüft zusätzlich Kalender und Marker). Änderung von Datum/Status = Update desselben Termins; storniert/abgelehnt/gelöscht = Löschen; Duplikate werden bereinigt. Abgleich beim Laden und bei Änderung von Plan, Abwesenheiten oder Einstellungen in `CalendarScreen`.
- **Zurückstellen** eines Kalenders von Schreiben auf Lesen/Aus entfernt die dort geschriebenen Termine. Knopf **„Von Timetrack geschriebene Termine entfernen“** (mit Bestätigung) löscht alle Marker-Termine in allen änderbaren Kalendern (±2 Jahre). Optional „Eigenen Kalender „Timetrack“ anlegen“ (wird auf Schreiben gestellt).
- **Datenschutz wie E1**: Titel fremder Termine landen nie im Request und nie in geschriebenen Titeln (Test). Selbst geschriebene Termine (`isWrittenByTimetrack`) erscheinen nicht erneut als Kontext, egal in welchem Kalender.
- **Live Activity**: `glassEffect(.regular.tint(...))` für Pause/Weiter/Stopp (`LiveGlassFill`); bei „Transparenz reduzieren“ bleibt die deckende Füllung. Befund im iOS-27.1-SDK (swiftinterface): `WidgetTexture.glass`/`widgetTexture` gibt es nur auf visionOS; der Banner-Hintergrund ist das System-Material (`activityBackgroundTint(nil)` bleibt); `glassEffect` ist die einzige Glas-API im Widget-Inhalt. Dynamic Island (systemgesteuert, schwarz) und Uhr-Layout unverändert.

## NICHT geprüft
- Echtes EventKit-Schreiben/Löschen (mehrtägige ganztägige Termine, Zeitzonen, iCloud/Exchange-Sync, Berechtigungsfenster).
- Glas in der echten Live Activity (Sperrbildschirm, Insel, Uhr); nur In-App-Galerie gesichtet. „Transparenz reduzieren“ nur per Code.
