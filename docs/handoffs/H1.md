# H1 – Haptisches Feedback (iOS, iPadOS, watchOS, macOS)

Anlass (Nutzerwunsch 17.10.2026): Haptic Feedback in der App. Leitlinie nach Apple HIG: sparsam, bedeutungsvoll, einheitlich; nie bei passiven Aktualisierungen.

## Aufbau
- `TimetrackDesign/Haptics.swift`: `TTHaptic` (selection, tap, softTap, success, warning, error, start, stop, confirmDestructive), `HapticLevel` (Aus / Dezent / Normal, Standard Normal, lokal in `UserDefaults` `appearance.haptics`, nicht im Konto), `HapticPolicy` (Stufe und Ergebnis-Zuordnung, rein), `TTHapticEngine` (Stufe + Entprellung 80 ms + eingespritzter `HapticPerforming`), `TTHaptics.play(_:)` / `.handle(_:)` für Code ohne View, `View.ttHaptic(_:trigger:)` und `ttHaptic(_:whenBecomesTrue:)` (basieren auf `.sensoryFeedback`).
- Echte Ausgabe `SystemHapticPerformer`: iOS `UISelection/Impact/NotificationFeedbackGenerator`, watchOS `WKInterfaceDevice.play(.start/.stop/.success/.failure/.click/.retry)`, macOS `NSHapticFeedbackManager` (`.alignment`, `.levelChange`, `.generic`). Spielt nur, wenn die App aktiv ist (App Intents, Hintergrund und Widgets lösen nichts aus; dort ist der Code gar nicht verdrahtet).
- Kern: `StoreOutcome` (timerStarted, timerStopped, saved, deleted, failed) und `onOutcome` an `TodayStore`, `TimeListStore`, `PlanningStore`, `CalendarStore`, über `AppModel.onOutcome` weitergereicht. Gemeldet wird je Benutzeraktion genau einmal; Ladevorgänge melden nichts, ein fehlgeschlagener Lesezugriff ebenfalls nicht (nur der Fehlerhinweis), ein Wiederholversuch nach Netzfehler zählt nicht doppelt. Die Apps setzen `model.onOutcome = { TTHaptics.handle($0) }`.
- Einstellung „Haptisches Feedback“ (Aus / Dezent / Normal, „Probieren“ spielt Erfolg) auf der Darstellungsseite (iOS). „Dezent“ spielt nur Ergebnisse (start, stop, success, warning, error, confirmDestructive), keine Auswahl-/Navigationstakte. watchOS und macOS haben keine eigene Einstellung (Standard Normal bzw. dieselbe lokale Einstellung, falls gesetzt).

## Zuordnung Interaktion zu Haptik
| Interaktion | Haptik |
| --- | --- |
| Timer starten / stoppen (Heute, Schnellaktion, Uhr, Mac) | start / stop (iPhone: mittlerer bzw. harter Impuls, Uhr: `.start`/`.stop`) |
| Speichern ok (Eintrag, Abwesenheit, Plan, eigener Tag, Urlaubseinstellungen/-korrekturen) | success |
| Anfrage fehlgeschlagen | error, einmal je Aktion |
| Stornieren/Löschen: Bestätigung erscheint (Dialog, Void-Blatt, Serverwechsel) | confirmDestructive (Warnung) |
| Server bestätigt Storno/Löschen | success |
| Tab- und Seitenleistenwechsel; Art Arbeit/Fahrt/Schule; Kalendertag; Monat in der Auswahl; Akzentfarbe (iOS/Mac-Seite); Uhr: Art-Auswahl | selection |
| Woche/Monat vor und zurück, „Heute“/„Diese Woche“, Monatswischen, Pull-to-Refresh fertig (Heute, Zeit) | softTap |
| Bereichsauswahl: Start (Langdruck oder erster Tipp) | tap |
| Bereichsauswahl: Ende (zweiter Tipp) | success |
| App-Symbol gewechselt / fehlgeschlagen | success / error |
| Uhr: „Sitzung übernommen“ (Knopf in den Einstellungen, danach angemeldet) | success, sonst warning |

Nie: laufender Timer, Hintergrundaktualisierung, Widgets, Live Activity, Ladevorgänge, Tagesziel erreicht.

## Bewusst weggelassen
- Validierungsfehler (`warning`) in Editoren: die Speichern-Knöpfe sind bei ungültigen Eingaben deaktiviert, es gibt keine Fehlermeldung beim Absenden. `warning` ist für künftige Validierungsmeldungen vorhanden.
- Timer per Widget, Live Activity oder Kurzbefehl, während die App im Vordergrund ist: ein Haptik-Erfolg beim Erkennen der Änderung im Vordergrund wäre eine Reaktion auf eine passive Aktualisierung; Intents laufen nicht im App-Prozess mit Oberfläche. Die frühere Haptik bei jedem Wechsel von `running.id` (A6) wurde entfernt, weil sie auch bei Nachladen ausgelöst hätte; Start/Stop aus der Oberfläche melden stattdessen ihr Ergebnis.
- Toggles, Menü-Auswahl, Swipe-Aktionen, Beginn von Pull-to-Refresh: liefert das System selbst, keine zweite Haptik.
- Einstellung auf der Uhr und der Mac-Einstellungsseite; die macOS-Haptik ist nur für Aktionsergebnisse und Auswahl verdrahtet.

## Nicht geprüft
- **Wie sich die Haptik anfühlt**: Der Simulator spielt keine Haptik. Weder Stärke, Reihenfolge bei schnellen Tipps noch die Abstimmung mit der System-Haptik wurden auf einem Gerät oder einer Uhr gespürt; macOS-Trackpad ebenso. Die Zuordnung ist eine begründete Annahme.
- Die Darstellungsseite mit der neuen Zeile wurde gebaut, aber nicht im Bild gesichtet oder per UI-Test bedient.
- Verhalten mit Systemeinstellung „System-Haptik“ aus oder im Stromsparmodus (das System unterdrückt dort selbst; die App fragt es nicht ab).
